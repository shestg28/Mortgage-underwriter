# Database Migrations

Alembic manages all schema changes for the MIL platform. This directory contains the migration environment and the versioned migration scripts.

## Configuration

- `alembic.ini` — at repository root; sets `script_location = migrations`
- `env.py` — Alembic environment; resolves database URL from environment variables
- `script.py.mako` — template for new migration files
- `versions/` — versioned migration scripts (one file per migration)

## Common commands

```bash
# Apply all pending migrations
make migrate

# Generate a new migration from model changes
make migrate-new MSG="add evidence_items table"

# View pending migrations as SQL (without applying)
make migrate-check

# View migration history
make migrate-history

# Roll back the most recent migration
make migrate-rollback
```

## Bounded context schema ownership

Each bounded context owns its tables in a dedicated PostgreSQL schema. Tables are added by migrations when the bounded context is implemented:

| Bounded Context | PostgreSQL Schema | Tables |
|---|---|---|
| Application & Party | `core` | `applications`, `parties` |
| Document Processing | `document` | `documents` |
| Evidence Management | `evidence` | `evidence_items`, `evidence_snapshots`, `evidence_relationships` |
| Policy Engine | `core` | `policy_packs`, `policy_rules` |
| Finding Management | `finding` | `findings`, `finding_party_refs` |
| Review & Verification | `review` | `verifications` |
| Audit & Governance | `audit` | `audit_events` (INSERT-only permission) |
| Operational Intelligence | `oi` | `queue_snapshots`, `sla_configs` |
| Integration Gateway | `integration` | `integration_configs`, `webhook_deliveries` |
| Identity & Access | `core` | `users`, `roles`, `role_assignments` |
| Intelligence Orchestrator | `orchestrator` | `workflow_runs`, `workflow_steps` |

## Adding models to autogenerate

When a new bounded context model is added, import it in `migrations/env.py` under the "Import bounded context models" block. Without this import, Alembic cannot discover the table and will not include it in autogenerated migrations.
