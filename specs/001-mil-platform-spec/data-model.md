# Data Model: Mortgage Intelligence Layer (MIL)

**Phase 1 Output** | **Branch**: `001-mil-platform-spec` | **Date**: 2026-06-29

---

## Design Principles

- Every table representing a domain event or extracted fact is **append-only or immutable**
  after creation (Evidence, Audit Events, Evidence Snapshots)
- Corrections use **supersession**, not updates (new record references superseded record)
- All core entities carry a `created_at` timestamp; mutable entities carry `updated_at`
- All tables are namespaced by bounded context schema: `core`, `evidence`, `finding`,
  `review`, `audit`, `oi` (operational intelligence)
- A reserved `tenant_id` column is present on all core tables to support future multi-tenancy
  without schema changes
- Soft-delete is not used — domain state is always explicit

```

NEEDS_REVIEW     # Flagged for human examination
VERIFIED         # Confirmed accurate by reviewer (terminal)
OVERRIDDEN       # Replaced by reviewer with corrected value (terminal)
ESCALATED        # Referred to senior officer or specialist
```

## Key Validation Rules

| Entity | Rule |
|---|---|
| `evidence_items` | `extraction_confidence` must be in range [0.000, 1.000] |
| `evidence_items` | `extraction_model_version` must be non-empty |
| `evidence_items` | `extracted_at` must be ≤ `created_at` |
| `findings` | All five explainability fields (`title`, `rationale`, `evidence_summary`, `confidence_label`, `recommended_action`) must be non-empty |
| `findings` | All four attribution fields (`model_version`, `prompt_version`, `policy_pack_id`, `extraction_version`) must be present |
| `findings` | `confidence_score` must be in range [0.000, 1.000] |
| `findings` | At least one `evidence_snapshot` record must exist before a finding can leave EXTRACTED state |
| `verifications` | `reason` is required when `action` is OVERRIDE or ESCALATE |
| `verifications` | `new_value` is required when `action` is OVERRIDE |
| `verifications` | `previous_state` must match the current `lifecycle_state` of the referenced finding |
| `finding lifecycle` | Terminal states (VERIFIED, OVERRIDDEN, RESOLVED) cannot transition to any other state |
| `policy_packs` | Only one policy pack per tenant may be active (null `deactivated_at`) at any time |
| `audit_events` | `sequence_number` must be monotonically increasing with no gaps |

## Entity Relationship Summary

```
core.applications
  ├── core.parties (1:many)
  ├── document.documents (1:many, via party_id)
  ├── evidence.evidence_items (1:many, via application_id)
  ├── finding.findings (1:many, via application_id)
  └── core.policy_packs (many:1, active pack)

document.documents
  └── evidence.evidence_items (1:many, via document_id)

evidence.evidence_items
  ├── evidence.evidence_relationships (many:many, self-referential)
  └── evidence.evidence_snapshots (1:many, via evidence_item_id)

finding.findings
  ├── evidence.evidence_snapshots (1:many, via finding_id)
  ├── finding.finding_party_refs (many:many via parties)
  └── review.verifications (1:many)

review.verifications → audit.audit_events (every verification write emits an audit event)
finding.findings → audit.audit_events (every state transition emits an audit event)
```
